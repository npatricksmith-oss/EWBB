# Team Ball Notes — revision pass

Changes are left uncommitted for the coordinator, as requested. No engine or architecture files changed.

- Replaced the flat seam drawing in `src/ui/baseballSprite.js` with a normalized, closed two-lobed spherical seam (`0.65 cos(t) + 0.35 cos(3t)`, `0.65 sin(t) - 0.35 sin(3t)`, `0.75 sin(2t)`). Rodrigues rotation turns the points around the selected 3D spin axis; orthographic projection draws only points on the front hemisphere (`z > 0`). Uses 24 orientations per axis, red seams/darker stitch pixels, rasterized two-tone leather, and a one-pixel dark silhouette. Tiny offscreen canvases and disabled smoothing preserve the chunky look.
- `drawPixelBaseball(ctx, x, y, radiusPx, spin, opts)` retains its cumulative-radian spin argument. `opts.axis` accepts `back`, `top`, `side`, or `{x,y,z}` (normalized internally); the sprite cache includes size, orientation, normalized axis, and tint, with a 2048-entry cap. `opts.tint` colors the ball leather itself; it no longer draws a surrounding halo.
- Added exports `getVisualBallSpin({pitchType, spin, contact, launchVector, isThrow})` returning `{axis, fps}` and `visualSpinAngle(fps = 12, timeMs = performance.now())`. The latter advances one cached orientation per visible step at 10–14 fps. Fastballs use horizontal backspin, curves reverse it for topspin, sliders use a tilted side axis, and changeups animate more slowly. Throws always use backspin.
- Batted balls use `physicsResult.spin = {backspinRpm, sidespinRpm}` when available (positive backspin, negative topspin, signed sidespin). Otherwise `physicsResult.contact` can be a type string or an object with `type`/`contactType` and optional `launchAngleDeg`; ground contacts use topspin and flies use backspin. The launch vector's angle is the final fallback. This metadata is carried into full-field playback and replay; spin no longer flips merely because a descending fly gets close to the ground.
- Removed the 13px plate call ring entirely. For pitches not put in play, the pixel ball turns red for strikes/fouls or green for balls from normalized flight time `t >= 0.85`. At the crossing, a small colored pixel ball and label remain after the pitch animation clears, until `animatePlay` starts the next pitch. Coordinates are stored relative to the zone so resizing preserves placement. The catcher mitt's legacy outlined white ball is suppressed in the duel caller. Existing contact-flash rays remain for contact.
- Wiring: none required. The renderer imports the helper exports directly and already reads the forthcoming physics spin/contact metadata. No camera/layout changes.
